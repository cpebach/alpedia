# Alpedia（プロトタイプ）

Minecraft と KSP を組み合わせたような、物理演算付きボクセルサンドボックス。
「方針.txt」（alpedia フォルダの docs）に沿って作った、一通り動く最初の土台です。

## 起動

1. Python 3.10 以上を入れる
2. このフォルダで `pip install -r requirements.txt`
3. `start.bat` をダブルクリック（または `python run.py`）

起動するとメニュー画面が出ます（初回はシナリオのワールド `scenario` が自動で作られます。シナリオはメニューの「シナリオ」から、いつでも新しく始められます）。

### Rust の画面（試験版）

`native\build_windows.bat` で作ると `lib\alpedia_view.pyd` ができ、`python run.py --view rust --world 名前` で、
画面を Rust（wgpu）で描く試験版を開けます。今の版で描く物は、構築物（ブロック・遠景の箱・ライト・機器の記号）・地表と掘った跡・
惑星・景色の箱・空の色です。歩く（WASD・Space・Ctrl）・見回す（クリックでマウスを閉じ込め、Esc で外す。もう一度 Esc で終わる）・
ジェットパック（F）・保存（F5）ができます。文字（HUD・看板）・メニュー・道具・人物・MOD の画面側はまだで、fps は窓のタイトルに出ます。
今までの画面（Panda3D）は今までどおり `start.bat` / `python run.py` で使えます。

### メニュー画面

- **遊び方を選ぶ**（上の3つのボタン）: **シナリオ**（シナリオの一覧から選んで最初から）・**サバイバル**（MOD なし、惑星ガイア）・
  **クリエイティブ**（MOD なし、惑星ガイア。出現地点のそばに見本の「はじめのロケット」）を、おすすめの設定ですぐ始めます。
  どれも完全剛体モード（軽い）で始まります
- **続きから**（ワールド一覧）: クリックで選択、選択中をもう一度クリックするか「遊ぶ」で開始。ストーリーのワールドは今の章を表示
- **詳しく設定して作る…**: 名前（半角英数字）、遊び方（クリエイティブ／サバイバル）、惑星（地球型／球体）、ボクセルサイズ、重力倍率、自動削除、
  完全剛体モードと、「MOD を選ぶ…」の画面で MOD を選んで作成
- **完全剛体モード**（新規作成・ワールド設定。既定は ON）: 構築物を丸ごと1つの剛体として計算します（曲がらない・壊れない。軽い）。
  OFF にすると、ブロックがやわらかく曲がる・ちぎれるようになりますが、負荷が増えて重くなることがあります
- **MOD を選ぶ…**（新規作成・ワールド設定）: MOD の一覧（説明・必要な MOD）。押すと入れる／外す。ほかの MOD が必要な MOD（`mod.json` の `requires`）を入れると、必要な MOD も一緒に入ります（★）。必要とされている MOD を外すと、それを使う MOD も外れます
- **MOD**: 街・場所・ブロック・見た目などを足す MOD は、ワールドごとに新規作成／ワールド設定の MOD 選択で入れます（シナリオの MOD は「シナリオ」から）。
  MOD はワールドを始めるときに一括で読み込み、エラーがあればそのとき一覧を出してワールドを始めません（プレイ中に読み直しはしません）。
  使っている MOD を外したワールドは始められなくなるので、**MOD を作る・入れる・外す前にワールドのフォルダをコピーしておく**ことをすすめます（`mods/README.md`）
  （取引・部屋は、サバイバルのワールドに「サイバーパンクの街」を入れると使えます）
- **マルチプレイ（LAN）**: 同じ LAN の中で一緒に遊べます（下の「マルチプレイ（LAN）」）
- **ワールド設定**: 選択中のワールドの上記設定と、自動削除の距離・時間・頂点数、MOD の ON/OFF を変更
- **削除**: 確認画面のあと、ワールドのフォルダごと削除（元に戻せません）
- **ゲーム設定**: 解像度・フルスクリーン・BGM の音量・効果音の音量（それぞれ 0〜100 %）・視野角・描画距離・地表の細かさ・マウス感度・
  物理計算の精度（config/settings.json に保存）。音量はゲーム中の一時停止メニューでも変えられます

## 音（BGM・効果音）

- **BGM**: `mods/bgm/` に置いた曲（mp3）を、シナリオの章・ムービーに合わせて流します。曲の一覧と音の大きさの補正は
  `mods/bgm/bgm.json`、どの場面で何を何秒から流すかは `mods/story/code/script.py` の `BGM`。曲のファイルが無ければ BGM なしで
  遊べます（曲のファイルはリポジトリに入れていません）。ムービーの効果音と環境音はムービーの中、曲はゲームが重ねて流します。
  エンドロールの「音楽」に、流した曲の題名が出ます
- **効果音**: ブロックを置く・壊す、地面を掘る、機器を使う、操縦席に座る・降りる、置けない、推進機の点火と噴射、
  アクチュエーター（ローター・ピストン・ヒンジ）が動く音、ジェットパック。近くの推進機・アクチュエーターほど大きく聞こえます。
  音は `sauce/sounds/*.wav`（数式で作った物。作り直しは `python tools/make_sounds.py`）
- 音量は BGM と効果音で別々（ゲーム設定・一時停止メニュー）。ムービーの効果音は効果音の音量に従います

ゲーム中に Esc で一時停止メニュー（再開／保存／メニューへ戻る／終了）が開きます。

```
python run.py --world 名前        メニューを飛ばして指定ワールドで起動（無ければ空のワールドを作成）
python run.py --headless --steps 600   描画なしでシミュレーションだけ実行（動作確認用）
```

## マルチプレイ（LAN）

- **ホストになる**：ワールドで遊んで Esc →「LAN に公開（マルチプレイ）」。左上に IP アドレスとポート（既定 47620）が出ます。
  初めて公開するとき、Windows のファイアウォールの確認が出たら「許可」してください。
  **参加できないとき**は、ホストの PC で `LANで公開できるようにする.bat`（パッケージ版は `Alpedia` フォルダ、開発版は `dev` フォルダ）を
  実行します（ファイアウォールで TCP 47620・UDP 47621 を許可。管理者の権限が要ります）。
  会社などのネットワークでは、PC どうしの通信そのものが止められていることもあります（ネットワークの管理者に確認）。
  切り分けには、同じ PC で2つ起動して `127.0.0.1` に参加してみる（これで入れれば、ゲームではなくネットワーク側の問題）。
  参加を試みた結果（理由）は、参加する側・ホスト側それぞれの `logs/latest.log` に出ます。
- **参加する**：メニューの「マルチプレイ（LAN）」。同じ LAN で公開中のワールドが一覧に出るので押すだけです
  （出ないときは、ホストの IP アドレスを「IP アドレスで参加」に入れます）。名前もここで決めます。
- ワールド・セーブ・MOD はホストの PC のものを使います。参加すると、そのワールドの **MOD が自動で届きます**
  （自分の mods/ に同じ物があればそれを写し、違う・無い物だけ受け取ります。置き場所は `cache/net_mods`）。
- **保存はホストが行います**（F5・一時停止メニュー）。参加した人の位置・持ち物も名前ごとにホストのセーブ（`players.json`）に残り、
  次に同じ名前で参加すると続きから遊べます。
- 参加した人ができること：ホストと同じ（置く・壊す・掘る・E・機器の設定・プログラム・アクチュエーター・座って操縦・F8 の読み込み・街の取引）。
  サバイバルの持ち物は人ごとです。
- 参加した人が **F9 で出力した構築物は自分の PC**（`saves/.net/exports`）に入り、自分のワールドの F8 でも「マルチプレイで出力」として読み込めます。
- 見た目は Esc の「見た目 ◀ ▶」で人ごとに選べます（ひとりで遊ぶときも同じ）。ほかの人には頭の上に名前が出ます。
- マルチプレイ中は Esc で一時停止しても世界は止まりません。ホストが抜けると全員メニューに戻ります。
- LAN の中の知り合いどうしで遊ぶ前提の作りです（参加した人の操作をそのまま受け付け、MOD のプログラムもホストから受け取って動かします）。
  知らない人がいるネットワークでは公開しないでください。

## 操作

| キー | 動作 |
|---|---|
| WASD / マウス | 移動 / 視点 |
| Space / Ctrl | ジャンプ・上昇 / 下降（ジェットパック時） |
| F | ジェットパック ON/OFF |
| 左クリック | ボクセル削除・地面を掘る |
| 右クリック | 選択中の素材・機器を設置（地面に置くと新しい構築物） |
| ホイール・1〜9 | アイテムバー（画面下の9枠）から素材・機器を選ぶ |
| I | インベントリ：すべての素材・機器をアイコンで表示。クリックで持ち上げてアイテムバーの枠へ（Esc で閉じる） |
| R | 機器の向きを変更 |
| N | 目の前の空中に新しい構築物を作る |
| E | 機器の操作（推進機の点火・バルブ開閉・コンピューター起動・手回し発電 など）／操縦席に座る・降りる |
| P | 機器の設定メニュー：名前の変更（すべての機器）／コンピューターのプログラム編集／アクチュエーターの動作設定 |
| V | 三人称視点 |
| M | 目印の切替（最寄りの街 → 自宅 → なし） |
| K | マップ（訪れた都市・都市への助言） |
| F5 / F9 / F8 | 保存 / 見ている構築物を OBJ 出力 / 読み込みメニュー |
| F10 / F11 / F12 | （ursina 組み込み）描画モード切替（ワイヤーフレームなど。もう一度押すと順に戻る）/ フルスクリーン / 開発用表示 |
| F3 | 開発用の表示（処理の重さ・頂点数・物理コアなど。ふだんは高度・速さだけ） |
| Esc | 一時停止メニュー（再開・保存・メニューへ戻る・終了・リスポーン・読み込み・OBJ 出力）。開いた画面（J・I・F8 など）は Esc か「閉じる」で閉じる（同じキーをもう一度押しても閉じない） |

操縦席に座っている間は、推進機に割り当てたキー（既定 Space）で点火、X でアクチュエーターの設定動作を実行。
キー入力はコンピューターのスクリプトからも読めます。

- **キーの変更・操作の一覧**：Esc（一時停止メニュー）→「操作とキー設定」、または F1、またはメニューの「ゲーム設定」→「操作とキー設定」。
  キーのボタンを押してから割り当てたいキーを押すと変わります（ほかの操作と同じキーなら入れ替え）。
- **画面のボタン**：右上にカメラ・視点・持ち物・メニュー（街の MOD があればマップ・目印）、右下にジャンプ・掘る・置く・ジェットパックなど
  （操縦席では「降りる」と、機器に割り当てたキー・プログラムが読むキー。Space は「上昇」など意味の名前で出ます）。
  読み込み（F8）・OBJ 出力（F9）・保存（F5）は一時停止メニューの中にもあります。キーボードで遊ぶときは **Alt を押している間カーソルが出て**押せます。
- **近づくと出るボタン**：操縦席・機器・お店・NPC などに近づくと、画面右に機器1つにつき1つボタンが出ます（押す・E で使う。右の歯車は P の設定）。
  配管・バッテリーは出しません。シナリオでは今の目標の機器がいちばん上に来ます。
  E は見ている物が使えなければ、いちばん上のボタンの物を使います（ガラスごしに見ているときは、向こうの人物を先に）。
- **座ると三人称**：操縦席に座ると自動で三人称（乗り物の大きさに合わせて離れ、壁の向こうには入りません）。降りると元の視点。V で切り替え。
  ドローンの操縦台では、ドローンを後ろから映します。
- **リスポーン**（一時停止メニュー）：HP はありません。宇宙に飛ばされた・出られなくなったときに使います（自宅の部屋か最初の出現地点へ。
  シナリオでは今の章の始めの場所へ）。**サバイバルでは手持ちの資源をなくします**（お金と、部屋の収納箱に預けた物は残る）。
- **カメラモード**（右上のカメラのボタン・C）：自撮りや建造物の撮影用。自分のまわりをカメラが回り（ドラッグ・なぞる）、
  ホイール・2本指で距離、WASD・Space・Ctrl で注目する所を動かせます。パネルで画面の表示・ブロックの枠の表示、
  モーション（`cute_motions` などの MOD）、体の向き、高さ、視野角、傾きを変えられます。**「写真を保存」（P）** で、パネルを隠した
  画面を `photos/<ワールド>_<日時>.png` に保存します。「パネルを隠す」で画面をすっきりさせることもできます
  （画面を1回タップ・クリックか H でパネルが戻ります。Esc か「カメラモードを終わる」で終わる）。
- **タッチ操作（仮想ジョイスティック）**：一時停止メニューかゲーム設定で ON。左下のスティックで移動、画面のほかの所をなぞって視点、
  ボタンで操作します（マウスで視点を回さなくなります）。Windows で複数の指が使えればスティックと視点を同時に動かせます
  （使えない PC では指1本ずつ）。
  - **タップ**：触った物を使う（使えない物なら、そこにブロックを置く）
  - **長押し**：触っている所を壊す・掘る（押している間くり返す）。「掘る・壊す」「置く」のボタンも長押しでくり返します
  - 照準の先の物が使えるときは「使う」「設定」のボタンが出ます

### シナリオモード（ストーリー vol.1）

「新規作成」→「MOD を選ぶ…」で **シナリオモード（ストーリー vol.1）** を入れて作ります（初めて起動したときは `scenario` が自動でできます）。
シナリオに必要な MOD（シナリオ再現ブロック・登場人物・ルナ・ポート・軌道都市アマツ・VRM の見た目）は一緒に入ります。
前の版のチュートリアルのワールドも、必要な MOD を足して続きから遊べます（章は新しい章立てに読み替えます）。

惑星ガイアに落ちた少女トワ（N 財団に作られた「三号」）が、無線の声ミカガ・情報屋サクラに導かれて観測基地 ALP-7 の設備を動かし、
ルミナス号を直して月の自由港ルナ・ポートへ。艦隊戦・ロボットの一騎打ち・落ちていく軌道都市アマツを経て、三つ目の道を選ぶ物語です（約 100 分）。
最後はガイアの発射台でみんなと話して記念写真を撮り、ロケットで旅立ちます（打ち上げ → ブースター分離 → 低い軌道 → エンドロール →
ワールドの選択に戻る）。シナリオのワールドは完全剛体モードで作ります（前の版のセーブは惑星テラのまま続きから遊べます）。
章の区切りにムービー（`mods/story/movies/`。Esc・クリックで飛ばせる。J の一覧から見直せる）。

- 左上に章と目標（済むと ■）、画面の下にセリフ（【無線】）、目標の場所に目印、置く場所には光る枠が出ます。

- プログラムの課題（クレーン・姿勢制御・迎撃・再加速）は、1 分たっても完成しないと、次に置くブロックや入れる数字が光ります。
- 物語の途中は、使える機器・ブロックプログラムの種類が章ごとに増えます（まだ使えない物はアイテムバーで薄く出る）。
  F8 の設計図はクリアしてから使えます。
- ワールドは完全剛体モードです（構築物は曲がらない・壊れない。軽い）。
- 建物もブロックです（アンカーで固定。中に入れて内装があります）：ガイアの観測基地（本館＝事務室、電源・作業小屋、格納庫、倉庫、
  工場の屋根、電波塔、発射台の整備塔）、ルナ・ポート（管制塔＝受付と管制室、居住・温室・研究のドーム、住居、通路、ソーラーパネル、
  電波の皿、探査車）、アマツの甲板（機関室・倉庫・詰め所）。宇宙の艦隊も 2 m のブロックの艦で、連盟は箱っぽく無骨、
  帝国は潜水艦・飛行船のような流線型です（ミサイルは当たりません）。迎撃艦は甲板の下の船体・推進の箱・艦橋の操作盤つき。
  触れる物（端末・受付など）・地形のような大きな物（尾根・道・アマツの円筒・発着場の台）は景色の箱のままです。
  明かりは全部ライトのブロック（建物のバッテリーで光る）：基地の明かりは電源を入れると点き、アマツの非常灯は落ちていく間だけ赤く点きます。
- ルミナス号は屋根つきの2段式ロケットです。前後に燃料ブースター（推進機2つ・タンク・バルブ）がアクチュエーターの留め具で
  ついていて、航法プログラムがブースターの燃料が減ると留め具を外して切り離し（第1段 → 第2段）、本体だけで月へ向かいます。
  ルナ・ポートとアマツの建物は場所の MOD が作るので、ほかのワールドに入れても建物が建ちます（ワールドに1回だけ。壊した物は作り直さない）。
- 動かない構築物（脱出ポッド・ビーコン・電源・装置・操縦台・遮断機・看板・クレーン・工場・迎撃艦・作業台・管制室）と、
  まわりの飾り（街灯・ソーラーパネル・旗・破片・立て札・柵・木箱・ドラム缶・机）は、アンカーのブロックで地面に固定した
  ブロックです（物理計算しないので軽く、ぶつかっても吹き飛ばない）。遮断機・クレーン・装置の動く所はアクチュエーターで動きます。
  前の版のセーブは、読み込んだときに動かない構築物の足もとへアンカーを足します。
- 宇宙では、トワ（作られた存在）以外の人はガラス張りの部屋の中にいます（窓ごしに E で話せる）。
- エンドロールの「お世話になったもの」は、`mods/story/credits/<名前>.png`（anthropic・python・rust・github など。
  `docs/ストーリー台本.md` に一覧）を置くとロゴの絵を出します（無ければ名前の文字）。公式のロゴ画像はそれぞれの配布元から入手してください。
  その後のテキスト・制作の名前は `mods/story/code/script.py` の CREDITS_* で直せます。
- シナリオは MOD「story」（`mods/story`）。人物は「登場人物（ストーリー vol.1）」（`mods/soredemo_cast`）、月の街は「ルナ・ポート」
  （`mods/lunaport`）、軌道都市は「軌道都市アマツ」（`mods/amatsu`）、砲塔・レーダー・ミサイル・推進モジュールは
  「シナリオ再現ブロック」（`mods/scenario_blocks`）から読み込みます。どれもほかのワールドに入れて使えます。
- シナリオの船・ロボット・艦は **F8 の「設計図」** に最初から並んでいて、必要な MOD が入っているワールドで出せます（作り直しは `python tools/make_blueprints.py`）。
  MOD のいらない「はじめのロケット／工場／気密室」と「変形ロボット ツバメ」も並んでいます（作り直しは `python tools/make_starter_blueprints.py`）。
- **変形ロボット ツバメ**（設計図）: ロケットと人型に変形するロボット。制御はブロックプログラム（コンピューターを P で見られます）。
  座ると胸のハッチが閉じて浮き、Q で変形します。降りると人型に戻って着地し、ハッチが前へ開きます（地面から乗り込めます）。
  高さは「今の高さ」を基準に保つので、地面でも船や甲板の上でも同じように浮きます。重力の弱い所（アマツ・月）では
  傾けられる角度を大きく、傾きを保つ係数を小さくして、ふらつかずに飛べるようにしています（第12章でトワが乗ります）。
  - 人型：W/S/A/D で動く、Space/Shift で上下、← → で向きを変える。足の裏の4つで浮き、腰のポッド（ヒンジ）で横へすばやく、
    背中のポッドと少しの前傾きで前へゆっくり加速します
  - ロケット：腕（ローター）を上げてひれに、腰と背中のポッドを下へ折り、推進機8つが全部下を向きます。Space で全開。
    加速は速いですが、曲がるのは推進機の出力の差で傾けるだけ（傾ける速さに上限）なので、小回りはききません
- 台本・目標の判定は `docs/ストーリー台本.md`、通しのテストは `tests/test_story.py`。

### 惑星の種類

新規作成の「惑星」で選べます（空のワールド）。

- **球体（テラ）**: なめらかな起伏の球体の惑星（従来どおり）。
- **地球型（ガイア）**: 山脈・丘・海・池（水たまり）・洞窟のある惑星。出現地点のまわりは平らな草原で、
  すぐそばに池、少し先に洞窟の入口、-Z 方向に山があります。
  - 水：海と池の水面より下では、構築物に浮力（押しのけた水の重さ）と抵抗がかかります。木は浮き、鋼鉄は沈みます。
    気密の空洞も水を押しのけます。プレイヤーは泳げます（Space で上、Ctrl で下、WASD で移動）。
  - 洞窟：地中をうねって続くトンネルと広間。入口から歩いて入れます。中は暗めに描かれます。
  - 山の横から掘ってトンネルを作ることもできます（掘った跡や洞窟の中は詳細なメッシュで描画）。
  - 地形はすべて `seed` から作られるので、`sauce/base/planets/base.json` の `seed`・`mountain_height`・
    `caves`（洞窟の数）・`ponds`（池の数）・`sea_level` を変えると別の地形になります（MOD でも定義できます）。

## 仕組み

- **丸いブロック**（かたい素材は角ばった多面体）: ブロックは球の形で、結合したブロック同士の間は埋まります（2つなら両端が丸い円柱、
  階段状に並べるとスロープ、平らに並べると角の丸い板）。見た目と当たり判定（地面・構築物どうし・プレイヤー）は同じ形です。
  素材の `"facet": true`（岩・鋼鉄・アルミ・ガラス）は、見た目だけ球の代わりに面・辺・角を落とした多面体で太らせます
  （つなぎ目・斜面の埋まり方は同じ。当たり判定は丸い形のままなので坂では転がります。角の出っ張りは 1 cm ほど）。
  形は結合に沿って作られるので、ちぎれると間の埋まりも消えます。
  アクチュエーターで回る部分は別の形として描くので、回してもつなぎ目がねじれません（境はセルの面でまっすぐ切れます）。
- **見た目**: テクスチャは 16×16 のピクセルアート（`sauce/textures/px_*.png`、近くでもにじませない）を、
  三角形ごとにいちばん近い軸の面へ投影して貼ります（1ブロックに1枚。向きの変わり目でも引き伸ばされません）。
  ブロックの境目に輪郭の線、くぼんだ所に軽い陰（環境光の遮り）を付けます。
  `config/settings.json` の `graphics.block_edges`（輪郭の線）・`graphics.block_ao`（陰）で切り替えられます。
  テクスチャの無い機器は `px_device.png`（機器の外板）を使います。
  この形を作るのに `scikit-image` を使います（必須）。
  ブロックを狙ったときの枠と、OBJ 読み込み時のボクセル化は立方体のままです。OBJ 出力は丸い形で書き出します。
- **ポリゴンのボクセル**: 各ボクセルは自分の8頂点を持ち、隣のボクセルと同じ位置の頂点同士が結合しています。
  素材の `stiffness`（形の保ちやすさ）、`joint_stiffness`（頂点間の動きにくさ）、`break_distance`（ちぎれる距離）、
  `plasticity`（曲がったまま戻らない度合い）、`rebond`（近づくと再結合）で、固体・液体・靭性・硬度を表現します。
  ちぎれると自動で別の構築物に分かれます。静止した構築物は計算を止めて（スリープ）軽くしています。
- **電力**: 配線不要。同じ構築物にある電気を作る物（燃えている推進機・太陽光パネル・手回し発電機）・バッテリー・消費機器で共有されます。
- **配管**: 配管ポートを持つ機器（配管・タンク・推進機・精錬機・加工機・通気口・バルブ）が、結合した連続ボクセルで繋がっている必要があります。
  面で接して続いているひとかたまり（区画）の中では、燃料も物資もすぐに流れます。
- **バルブ**: 区画と区画のあいだに入れ、開き具合（0〜100%。E で開閉、P で開き具合）× 最大流量（6 kg/秒）だけ通します。閉じると通しません。
- **推進機**: E（操縦席では割り当てたキー、スクリプトでは `t.ignite()`）で**点火**します。点火のときだけ電気を 20 kJ 使い、
  燃えている間は燃料（全開で 6 kg/秒）を使って推力と**電気**（全開で 20 kW）を出します。
  - タンクと直接（または配管で）つながっているだけだと、点火したら燃料が尽きるまで全開で燃え続けます（固体ロケットのように止められない）。
  - あいだに**バルブ**を入れると、バルブの開き具合で燃料の量＝推力（と発電）を変えられ、閉じると火が消えます（開けたら点火し直す）。
  - 1つのバルブの先に推進機がいくつもあると、通る燃料を分け合います。
  - 発電だけしたいときは、推進機を背中合わせ（反対向き）にして押す力を打ち消す、バルブを少しだけ開ける、などの工夫をします。
  - 燃料を使う「発電機」ブロックはなくなりました（前の版のワールドの発電機は配管に置き換わります）。
- **物の流れ（精錬機・加工機・タンク）**: 精錬機・加工機は原料を配管でつながった所（タンク・ほかの機械が作った物）から自動で受け取り、
  作った物は自分の中にためます。つながっていれば、精錬機の鉄は加工機へ、燃料はタンクや推進機へ自動で流れます。
  直接接していない（配管でもつながっていない）機械のあいだでは流れません。バルブを挟めば、バルブで止めたり流す量を変えたりできます。
  例：精錬機にバルブ越しにタンクと推進機をつなぐと、タンク側のバルブが開いていればできた燃料がタンクへ、推進機側が開いていれば推進機へ、
  両方開いていれば両方へ流れます。
- **気密**: ボクセルで完全に囲まれた空洞を自動で検出し、通気口で与圧・減圧できます。
- **アクチュエーター**: 向きを付けて置いたブロックの「出力面」の先を動かします。電力を使います。3種類あります：
  - **ローター**（青）: 回転（角度・速度）
  - **ピストン**（緑）: 押し出し／引き込み（最大ブロック1つ分・速度）
  - **ヒンジ**（橙）: 曲げる（下を参照）

  分離・結合（別の構築物とも可）はどの種類でもできます。P の動作を「なし」にすると、E・操縦席の X では動かず、
  コンピューターのプログラムだけで動かせます。操作は2通り：
  P で動作の種類・量・速度を設定して E で実行（操縦席では X）、またはコンピューターから
  `a = api.device("名前")` → ローターは `a.rotate(90, speed=45)`、ピストンは `a.extend(1.0)` / `a.retract(1.0)`、
  どれでも `a.detach()` / `a.attach()`（種類にない動作はエラーになります）。
  古いセーブの「アクチュエーター」は、押し出しを使っていたものはピストンに、それ以外はローターになります。
  回転・押し出しは格子に沿って結合しているブロックに伝わります（ずれて結合した場合は固定のみ）。
  別の構築物と結合した直後（1 秒）は、地面や相手にめり込んでいた分を押し出しても勢いにしません（位置だけ直して、
  速さの変化を 30 m/s² までにおさえる）。給油車などをつないだ瞬間に吹き飛ばないように。設定は `physics.merge_settle_time`
  （秒、0 で無し）・`physics.merge_settle_acc`（m/s²）。
- **ヒンジ**（機器「ヒンジ」）: アクチュエーターの仲間で、ブロックの中心を軸に、出力面の先を -90〜+90° 振ります（扉・腕の関節・跳ね橋など）。
  P で角度を決めると、E を押すたびにその角度と 0°（まっすぐ）を行き来します。
  曲がる側は置き方で決まります：R で出力の向きを決め、置くときに見ている側（出力の軸に垂直な4つのうち、いちばん近い側）が + の向きです
  （置いたときに「+ の角度で +Z 側へ倒れます」と出て、その側の面に曲がった矢印の記号が付きます）。
  操作はアクチュエーターと同じ（P で「曲げる」角度・速さ、E で実行、操縦席では X、スクリプトは `rotate()` / `rotate_to()`、
  ブロックは「□ を □ 度回す・曲げる」「□ の角度を □ 度にする」）。押し出しはできません。
  ヒンジの関節も Rust の物理コアで計算します（古い Rust の物理コアのままだと、ヒンジのある構築物だけ numba で計算します）。
- **アンカー**（機器「アンカー」、いかりの印）: アンカーのある構築物は惑星に固定されます。物理計算をしない（当たり判定はある）ので、
  ずれていかず、ぶつかられても吹き飛びません。地面に置けて、地面にめり込ませた形でブロックを置いても押し出されません
  （建物・看板・飾りの土台に）。
  - アクチュエーターの先の部分は動きます（それぞれの可動範囲で）。アンカーのある部分だけが固定です。
    アクチュエーターの両側にアンカーがあるときは、どちらも固定（動かせません。機器にそう出ます）
  - アンカーとつながっている部分と離れた（壊れた・外した・アンカーを取った）部分は、ふつうに動く構築物になります
  - アンカーで固定された構築物と固定されていない構築物をアクチュエーターで結合すると、固定されていない側が
    固定されている側の格子の位置に合わせられます（固定されている側が引き寄せられることはありません）
  - 柔らかいブロックのモード（完全剛体モード OFF）でも、アンカーのある構築物は剛体（＋関節）として扱います
- **ライト**（機器「ライト」、電球の印）: 電気（40 W）で光るブロック。同じ構築物にバッテリーなどの電気が要ります。
  E で点ける・消す。状態の color（光の色）・blink（点滅の周期 秒）・group（まとめて点ける名前。MOD は
  `buildkit.set_light_group(world, 名前, True/False)`）を持てます。電気が切れると消えます。
- **アンテナと無線通信**: アンテナ（電力 100 W、届く距離 3000 m）のある構築物どうしは、コンピューターから情報をやり取りできます。
  `api.send("チャンネル", 情報)` で送り、`api.receive("チャンネル")`（前回より後に届いたもののリスト）か
  `api.latest("チャンネル")`（いちばん新しいもの）で受け取ります。情報は数値・文字・True/False/None と、それらのリスト・辞書。
  届く距離は送る側と受ける側のアンテナの短いほうで、送ったものは 2 秒間だけ届きます。自分の構築物が送ったものは受け取りません。
  アンテナが無い・電力が来ていない・OFF（E で切り替え）の構築物では、この3つの関数はエラーになります（`api.antenna` で確かめられます）。
  電力・信号は構築物の中で共有なので、アンテナは構築物のどこにあっても使えます。ブロックプログラムでは「通信」の
  「チャンネル □ に □ を送る」と、値の「通信の受信値」「チャンネル □ に届いている」「アンテナが使える」を使います。
- **機器の記号**: 機器ブロックの表面には、インベントリのアイコンと同じ種類の記号が付きます。向きのある機器（推進機・
  アクチュエーター・コンピューター・操縦席）は、横の面の黄色い ▲ が機器の向き、向いている面は黄色い輪、反対側の面は薄い記号です
  （推進機は ▲ の方向に押します）。`config/settings.json` の `graphics.decal_distance`（既定 30 m）より遠い構築物では表示しません。
- **機器の名前**: 機器を見て P（コンピューター・アクチュエーターはメニュー内の「名前を変更」）で名前を付けられます。
  同じ名前の機器はコンピューターからまとめて動き、名前を分けると `api.device("推進機左")` やブロックの機器選択で個別に制御できます。
  「同名に番号を振る」で同じ名前の機器に 1, 2, 3… と番号を付けられます。名前はキーボードで入力します。
  名前を変えると、その構築物のブロックプログラム内の機器名も自動で置き換わります。
- **ブロック（ノード）プログラミング**: コンピューターの P 画面で「ブロックで編集」を押すと、スクラッチのように
  ブロックを並べてプログラムを作れます。左のパレットのブロックを押すと選んだ行の下（「＋ここに追加」を選べばその中）に入り、
  入力欄の中の値・計算・センサーも、スクラッチのような入れ子のブロックで表示されます
  （演算・比較は緑、センサー・機器の値は水色、変数は赤橙、通信はピンク、矢印は紫。数値の欄は白、条件は角ばった形、数値・文字は丸い形、
  矢印は右がとがった矢印の形。同じ色のブロックが入れ子になると、内側が少し明るくなります）。
  - **値・条件のブロックの入れ方**: 入力欄を1回押して選び（黄色い枠）、左のパレットの「演算」「センサー」「変数」「通信」にある
    値・条件のブロックを押すと、その欄に入ります。演算（＋ − × ÷ など）を入れると、今の値が左側に入ったまま包まれ、
    右側の欄が選ばれるので、続けて押していけば「誤差 を（目標 −（姿勢モーター の 出力の向き））にする」のような式が作れます。
    入れられない欄（数値の欄に文字など）は暗く表示されます。条件は数値の欄にも入れられます（はい＝1、いいえ＝0）。
  - 選んである入力欄をもう一度押すと、数値・文字の入力や、選ぶ画面（センサー・計算・比較・変数など）が開きます。
  - 「＋ ▼」「の 出力の向き ▼」のような ▼ を押すと、演算や比較の種類・機器の値の種類を選べます（かつ／または は押すたびに切り替え）。
  - センサー：高度・速さ・遠点・遠点までの時間・前への傾き・右への傾き・傾く速さ・右へ回る速さ・前への速さ・右への速さ・重力・座っている など。
    傾き・向きは、そのコンピューターが付いている部分（アクチュエーターの先で動く部分を除いた所）の向きで測ります（変形しても狂いません）。
  - **矢印（ベクトル）**: 向きと長さを持つ値です。パレットの「矢印」にあり、矢印の形の欄にだけ入ります。
    - 矢印のセンサー：速度・重力（近くのすべての天体の分を足したもの）・上向き・船の前／右／上・惑星の中心への矢印・位置。
    - 作る：「矢印 (x, y, z)」（▼ で ワールド／船から見た（右, 上, 前）を選ぶ）、「地点 (x, y, z) への矢印」。
    - 計算：矢印 ＋／− 矢印、矢印 ×／÷ 数、の向き（長さ 1 に）、の長さを □ までに、の □ に垂直な部分、を □ から □ 度以内に。
    - 数にする：の長さ、の 前／右／上／x／y／z 成分（前・右・上は船から見た向き）、内積、角度。
    - 「矢印の変数 □ を □ にする」で矢印を変数に入れ、パレットの矢印の変数のブロックで使います（数の変数とは別）。
    - 「矢印 □ を □ で見せる（□ 倍）」：構築物の重心から伸びる3Dの矢印で画面に見せます（物の向こうでも見え、約0.3秒で消えるので
      「ずっと」の中で使う）。色ごとに1本。行きたい速度・推力の向き・重力などを見ながら調整できます。
    - 演算に「マイナスなら0」を足しました。
    - 例：ルミナス号の航法プログラム（`scripts/moon.blocks.json`）は「行きたい速度 − 速度」の矢印から推力の向きを決めて月まで飛びます。
  イベント（起動したとき／ずっと／キーを押している間／押したとき／条件になったとき）、制御（もし・でなければ・くり返し・タイマー・停止）、
  アクチュエーター（推進機の点火・バルブの開閉と開き具合・ON/OFF、アクチュエーター・ヒンジの回転・曲げ・押し出し・引き込み・分離・結合、
  MOD の機器の迎撃砲塔・ミサイル発射機など。前の版の「機器」「迎撃・ミサイル」はここにまとめました）、表示、変数のブロックがあります。
  保存すると `scripts/<名前>.blocks.json` と、Python に変換した `<名前>.py` ができ、コンピューターはそれを実行します。
  「Python をコピー」で変換したコードをクリップボードにコピー、「Python で開く」でコンピューターの画面に移ります
  （「Python モードにする」で、変換したコードを Python として使えます。Python からブロックへの変換はありません）。
- **Python 制御**: コンピューターを見て P でコンピューターの画面が開きます。スクリプトの選択（前／次のファイル）・新規作成・
  実行・停止、print の出力とエラーの確認、名前の変更、ブロック編集への切り替えができます。
  スクリプトの編集はゲームの外のエディタ（メモ帳・VS Code など）で行います。「エディタで開く」でファイルを開き、
  保存するとゲームが自動で読み込み直します（実行中でも次の呼び出しから新しいコード）。
  使うエディタは、VS Code があればそれ、無ければメモ帳です。`config/settings.json` の `game.editor` に
  コマンドを書くと変えられます（例 `"editor": "\"C:\\Program Files\\Notepad++\\notepad++.exe\""`）。ファイルは `scripts/` にあります
  （「scripts フォルダを開く」「API 一覧（README）」のボタンもあります）。E で起動/停止。`tick(api)` が周期的に呼ばれます。
  `api.display("文字", width=3)` でコンピューターの表面に文字を表示できます（停止しても残るので看板として使えます）。
  `api.orbit()` で遠点・近点などの軌道情報も取得できます。
- **OBJ**: F9 で `exports/` に `.obj`・`.mtl`・`.alp.json`（素材割当て＋ボクセルデータ＋使っているプログラム）を出力。
  F8 で**読み込みメニュー**が開きます。
  - 一覧：このワールドの `imports/`・`exports/` と、ほかのワールドの `exports/`（コピーしなくても持ってこられます）。
    「imports を開く」でフォルダを開き、ファイルを置いたら「一覧を更新」。
  - ゲーム内で作った構築物（`.alp.json` にボクセルデータあり）は、ボクセル・機器・結合をそのまま再現し、
    プログラムも `scripts/` に入ります（同じ名前で中身が違うものが既にあれば、そちらを残します）。
  - 外部の OBJ（Blender など）は、**大きさ（いちばん長い辺 m）**・**細かさ（ボクセル 0.25/0.5/1 m）**・**素材**を指定してボクセル化します。
    元の大きさが 0.5〜40 の範囲ならその数値を m として、外れていれば（mm 単位など）8 m にして始めます。
    `.alp.json` の `"materials"`（usemtl名→素材ID）・`"scale"`・`"voxel_size"` があれば最初の値に使います。
  - 置いたときの大きさ・ボクセル数・素材と、サバイバルでは必要な資源と手持ち（足りないもの）を確認してから
    **OK** で目の前に置きます。何もせずやめるときは**閉じる**（または Esc）。
- **世界の広さ**: 制限なし（描画は浮動原点）。`world.json` の `cleanup` で、プレイヤーから一定距離以上・一定時間・
  電力なし・頂点数以下の構築物を自動削除します（`"enabled": false` で無効化）。
- **サバイバル**: サバイバルのワールドでは、設置に資源が必要になります。詳しくは下の「サバイバル」。

## サイバーパンクの街

惑星の地表と軌道上に、ネオンの光るビル街がほぼ一定の間隔で自動的にできます（惑星の seed から毎回同じ場所・同じ形）。

- **場所**: 惑星の地表に約 520 m おき（月は約 300 m おき）の候補地から、作れる所を選びます。候補地がだめなら近くを何か所か探し直し、
  街どうしは外周で 240 m 以上離します。小惑星には小さな前哨基地、惑星と月のまわりの軌道上にステーション型の「軌道都市」。
  - **山あい**: 15 m 四方の区画ごとに舗装した台を段々に作るので、斜面にも街ができます（高低差が大きすぎる急斜面は除く）。
  - **海沿い**: 水の上の区画は桟橋（水面より約 1.2 m 高い台）になり、水から階段で上がれます（ほとんど水の上・深い海は除く）。
  - 作らない所：出現地点のまわり。
- **歩きやすい地面**: 区画ごとに舗装し、高さは 25 cm 刻みでそろえます。55 cm までの段差は歩くだけで上れます（プレイヤーの自動の段差越え）。
  それより高い段差には区画の縁に沿った階段（1段 22 cm 以下、上に踊り場）、街の外の地面との間にも階段（地面に届くまで下りる）。
  1 m 以上の段差の縁には光る線が付きます。舗装・階段は壊れません。
- **目印**: 画面に最寄りの街の名前と距離を表示します（画面の外にあるときは端に ◀▶▲▼ で方向）。**M** で表示切替。
  地表近く（高度 60 m か惑星の半径の 15% の大きい方まで）では、軌道都市が近くても、いる惑星の地表の街（墜落した街を含む）を優先します。
- **描画の軽量化**: 街の外周から 100 m より遠い街は、建物を1つの箱だけで描く簡略表示（窓の模様・ネオン・看板・連絡通路なし、
  色にネオン色を混ぜて屋上を光らせる）。近づくと窓やネオンのある詳細表示になります（離れるときは 120 m で戻す）。
  2500 m より遠い街と、画面の外・惑星の裏側の街は描きません。箱の内側の面も描きません。
  距離は `config/settings.json` の `graphics.city_detail_distance`・`graphics.city_view_distance` で変えられます。
- **当たり判定**: 構築物もプレイヤーも建物にぶつかり、上に乗れます。右クリックで建物の上にブロックを置けます。
- **壊れる**: 約 7 m/s 以上でぶつかった建物は、低く崩れて暗くなり、ネオンが消えた「壊れた見た目」に。
  約 18 m/s 以上か、壊れた建物にもう一度強く当たると消えます。すべて壊れると「壊滅」。
- **軌道都市を動かす**: 街全体を1つの剛体（質量は数百 t）として軌道を計算します。
  - 構築物でゆっくり押すと、その分だけ街が動きます（押した力の反動）。
  - 街に直接置いたブロックは街に**固定**されます。既存の構築物も、街に触れた状態で機器以外のブロックを E で固定／切り離しできます。
    固定した構築物の推進機を噴かすと街ごと加速し、軌道を変えたり落としたりできます（例：推進機2基で約10秒噴かすと近点が約200 m 下がる）。
  - 地面に落ちると、ぶつかった建物が壊れ、止まった所で「墜落した街」になります（台座は残ります）。
- **保存**: 壊れた建物と軌道都市の位置・速度だけを `world.json` の `city_state` に保存します。
  街は MOD（`mods/city`）です。ワールド設定の MOD 選択で「サイバーパンクの街」を入れると作られます。
  既存のワールドで、読み込んだ時点で構築物と重なる建物は最初から取り除き、構築物が街の地面（舗装・階段）と重なる場合はその街ごと作りません。

## 街の暮らし（通貨・NPC・取引・部屋）

- **通貨**: クレジット（所持品の「クレジット」）。サバイバルで街のあるワールドに入ると最初に 200 もらえます。
- **内装のある建物**: どの街にも、店（商人）・不動産屋・住宅（何部屋か並ぶ）があります。地面の階が店や部屋で、上にビルが重なっています。
  入口の看板の色：店＝橙、不動産屋＝緑、部屋＝水色。中には明かり・カウンター・棚・ベッド・収納箱があります。軌道都市は甲板の上、
  前哨基地（小惑星）は店だけ。
- **NPC**: プレイヤーのような簡素な姿（体・頭・光るバイザー）。商人と不動産屋は店の中、住民は広場や甲板を歩いています。
  見て **E** で話す（住民はほかの街の値段のうわさなどを教えてくれます）。
- **取引（サバイバルだけ）**: 商人（またはカウンター）を見て E。1・10個ずつ・全部 を売り買いできます。店から買う値段は基準の 1.1 倍、
  店に売る値段は 0.9 倍。どの街でも、鉱石を買って精錬して鉄とケイ砂を売るだけで少しもうかる（約 +5〜40%）くらいの甘めの値段です。
- **地域で値段が変わる**（基準の何倍か。ほかに街ごとに ±7%）

  | 地域 | どんな街 | 安い | 高い |
  |---|---|---|---|
  | 平地の街 | ふつうの街 | — | — |
  | 海辺の街 | 桟橋のある街 | 燃料 0.5・水 0.3 | 硫黄 1.3 |
  | 火山の街 | 硫黄の採れる高い山の街 | 硫黄 0.4・燃料 0.85 | 鉄 1.15・部品 1.1 |
  | 軌道都市 | 軌道上のステーション | 鉱石 0.6・硫黄 0.6・星鉱石 0.6・鉄 0.7 | **燃料 3.0・水 3.0**・部品 1.3 |
  | 辺境の基地 | 月・小惑星 | 星鉱石 0.6・鉱石 0.9 | 燃料 1.8・水 2.0・部品 1.2 |

  例：海辺の街で燃料を買って軌道都市で売る、火山の街で硫黄を買って燃料にする、など。
- **部屋（サバイバル）**: 不動産屋で買う（平地 約 400、軌道都市 約 900 クレジット）か、値段の 1 割で 60 分（ゲーム内の時間）借りる。
  - 収納箱：資源やクレジットを預けられる（借りる期限が切れても中身は残り、また借りれば出せます）。
  - ベッド：休むと保存して、そこが自宅になります。**M** キーで目印を「最寄りの街 → 自宅 → なし」と切り替え。
  - 建物が壊れて消えると、その部屋は使えません。クリエイティブでは買わなくても使えます（取引はなし・NPC は話すだけ）。
- **保存**: 部屋の持ち主・賃貸の期限・収納箱の中身・自宅は `world.json` の `economy` に保存します。

## マップと都市の思惑

- **K** でマップ（訪れた都市）。街の外周から 30 m まで近づくと「訪れた」になり、マップに載ります。
  天体ごとのタブ・経度と緯度の地図（◇は軌道都市の今の真下）・地域の色・現在地・ニュースを表示します。閉じるボタン / Esc で閉じる。
- **都市の思惑（サバイバル・訪れた都市だけ）**: 都市は「緊張」（0〜100）をためます。
  - **野心**：短い間に大量の取引をされると強気になり（取引の勢いが 400 クレジットを超えた分だけ、最大 3／分）、ほかの都市の**征服**を計画します。
    征服された都市は、取引の傾向（地域）が征服した都市と同じになります。
  - **不満**：訪れてから 25 分取引がないと、2.5／分ずつ不満がたまり、ほかの都市への**攻撃**を計画します。
    滅ぼされた都市は建物の多くが壊れた廃墟になり、NPC はいなくなります（部屋は使えなくなり、収納箱の中身はどの街の不動産屋でも受け取れます）。
  - 取引をすると不満は下がり、何もなければ緊張は少しずつ下がります。
  - 緊張が 70 を超えると、いちばん近い都市を目標に計画を立て（ニュースとマップの赤い枠でわかります）、**12 分後**にまだ緊張が高ければ実行します。
    攻める側の力＝残っている建物の数×（1＋緊張/100）、守る側の力＝建物の数×（1＋0.6×防御）。守る側が上回れば退けます。
  - 速さの目安：放っておいた都市は訪れてから約 65 分、取引しすぎた都市は最短でも約 35 分で行動します。行動のあとは 20 分休みます。
- **助言**（マップで都市を選ぶ。訪れた都市ならどこからでも。通信費 20 クレジット・同じ都市へは 5 分あける）
  - **説得する**：緊張を 35 下げ、取引の勢いを半分に。緊張が 55 未満になれば計画は中止。
  - **防御を促す**：防御 +1（最大 3）を 30 分。攻められても持ちこたえやすくなります。
  - **攻撃の目標を変える**：計画中の都市の目標を、近くのほかの都市に変えさせます。
- 保存は `world.json` の `politics`（訪問・緊張・計画・防御・支配・滅亡・ニュース）。クリエイティブでは動きません（マップは見られます）。

## サバイバル

本体の遊び方の1つです（`world.json` の `"mode": "survival"`。プログラムは `main/survival.py`）。メニューの「サバイバル」か、
「詳しく設定して作る」「ワールド設定」の遊び方で選びます。前の版のサバイバルの MOD を入れたワールドは、読み込むとこの遊び方になります。
クリエイティブとの違いは「置くのに資源が要る」「ジェットパックに手持ちの燃料が要る」「目標がある」の3つです。HP はありません。

- **目標**（左上に次の2つ）: 鉱石を 30 集める → 精錬機を置く → 鉄を受け取る → 燃料を 100 ためる → 推進機の乗り物で 50 m まで飛ぶ →
  軌道に乗る → 月に降り立つ。済んだ目標は `world.json` の `survival.goals` に残ります。
- **リスポーン**（一時停止メニュー）: 自宅の部屋（街の MOD）か最初の出現地点へ戻ります。手持ちの資源はなくなります（お金と、部屋の収納箱に預けた物は残る）。
- **置く費用**: 素材はブロック1個で 鉱石 1〜2・鉄 2〜4・ケイ砂 3 くらい（1回掘ると鉱石 10）。機器は鉄 2〜40・機械部品 0〜5（精錬機・加工機は鉄 40）。
  持ち物（I）のアイコンの下に費用が出て、足りない物は赤くなります。
- **最初の所持品**: 鉄 250・ケイ砂 40・機械部品 12・燃料 60。精錬機（鉄40）・手回し発電機・太陽光パネル・タンクを
  すぐ作れ、少しだけ飛べます（既存のサバイバルワールドも、足りない分だけ一度もらえます）。
- **掘ると出るもの**（左クリックで 10 ずつ。狙うと何が出るか表示されます）

  | 場所 | 資源 | 見た目 |
  |---|---|---|
  | ふつうの地面 | 鉱石 | 地面の色 |
  | 山の上の方（テラでは高い所） | 硫黄鉱石 | 黄色いまだら |
  | 洞窟の壁のまわり 3 m・月（ルナ）・小惑星 | 星鉱石 | 紫のまだら |
  | 海・池の水面（クリック） | 水 | いくらくんでも減りません |

- **精錬機**（E で手持ちの原料を入れ、もう一度 E でできた物を受け取る。複数の原料は順番に処理。
  作った物は精錬機の中にたまり、配管でつながった加工機・タンク・推進機へは自動で流れる。中にためられるのは 400 まで）

  | 原料 | できる物 | 電力 |
  |---|---|---|
  | 鉱石 10 | 鉄 4・ケイ砂 3 | 5 kW × 2 秒 |
  | 硫黄鉱石 10 | 燃料 20 | 5 kW × 2 秒 |
  | 星鉱石 10 | 燃料 5・鉄 8・ケイ砂 6・機械部品 1 | 5 kW × 2 秒 |
  | 水 10 | 燃料 5 | **60 kW** × 2 秒（水は無限なぶん電気を多く使う） |

- **電気**: 手回し発電機（E 1回 5 kJ）、太陽光パネル（燃料なしで 1.5 kW。鉄6・ケイ砂6）、燃えている推進機（全開で燃料 6 kg/秒・20 kW）。
  同じ構築物の中で共有されます。サバイバルで置いたバッテリーは空から始まります。
  推進機で燃料を電気にして水から燃料を作ると必ず損をする（1 kg あたり約 3.3 kJ に対して 24 kJ 必要）ので、
  水の燃料化には太陽光パネルや手回し発電機の電気を使います。推進機は点火に 20 kJ 要るので、バッテリーか手回し発電機を用意します。
- **タンクへの給油**: タンクを狙って E で、手持ちの燃料を入れます（入りきらない分は手元に残ります）。
- **ジェットパック**: 噴射している間だけ手持ちの燃料を 1 kg/秒 使います（地上を歩くだけなら減りません）。燃料が 0 だと飛べません。
- **月と小惑星**: 新しく作るワールドには月（ルナ、4 km 先）と小惑星 3 つ（6〜8 km 先）があります。星鉱石が採れるので、
  ロケットで取りに行く価値があります（既存のワールドの天体は変えていません）。
- 量や電力は `sauce/base/devices/base.json`（レシピの `"power"`）・`sauce/base/planets/base.json`（`"deposits"`・
  `"cave_resource"`）・`sauce/base/players/base.json`（`"jetpack_fuel_rate"`）で調整できます。

## 軽量化の仕組み

大きな構築物や多数の構築物でも重くなりにくいように、状況に応じて計算のしかたを切り替えます
（`config/settings.json` の `physics` で ON/OFF・しきい値を変更できます）。

Windows では起動時に、このゲームだけ省電力の速度制限（EcoQoS）を切り、優先度を「通常以上」、タイマーの精度を 1 ms にします
（Core Ultra などのノート PC で、省電力のコアに回されて「CPU もグラフィックも使っていないのに重い」のを防ぐ。
`"performance": {"windows_boost": false}` で切れます）。F3 の重さの表示の「CPU メイン ○%」が 100% 近ければ1つのコアで手一杯、
低ければ何かを待っています。

1. **剛体化と静止**（`rigid_enabled`）：重力以外の加速度が小さく（25 m/s² 以下）、形がほとんど変わっていない構築物は、
   ブロックごとの計算をやめて形を保ったまま1つの剛体として動かします。推進機が大きな加速度を出したとき、速くぶつかりそうなとき、
   アクチュエーターが動くとき、ブロックを付け外ししたときは自動でブロックごとの計算に戻ります（壊れ方・曲がり方は残ります）。
   止まっていて、動いている他の構築物に触れていないものは静止扱い（計算しない）にします。
   剛体・静止中の構築物は丸い表面の形を作り直さず、位置と向きだけを動かして描画します。
2. **遠方のレール**（`rails_enabled`, `rails_distance` 既定 400 m）：プレイヤーから遠く、噴射しておらず、地面から離れている
   構築物は、重心の軌道と回転だけを計算します（軌道は正確に保たれます）。近づく・噴射する・地面に近づくと元に戻ります。

3. **読み込み距離と機能処理の距離**（ゲーム設定のスライダー。いちばん右の「全部」でこれまで通り）：
   - **構築物の読み込み距離**（`graphics.load_distance`、既定 400 m）：これより遠い構築物はブロックの形を作らず（作ってあれば捨てる）、
     それっぽい色の箱（2 m ごとにまとめた箱。いちばん多い素材の色）でまとめて描きます。記号・看板も出しません。
     近づくと本物のブロックを読み込みます。大きい構築物の形は裏のスレッドで作り、できるまでは箱のまま見せます
     （1 フレームに読み込む量にも上限があるので、近づいたときに止まりにくい）。
   - **機能処理の距離**（`physics.process_distance`、既定 1500 m）：どのプレイヤーからもこれより遠い構築物は、
     機器・プログラム・物理を止めます（その場で止まり、近づくと続きから動きます。レールに乗っている物は軌道だけ進みます）。
     遠くの設備を動かし続けたいときは、読み込み距離とは別に大きくできます。
4. **止まっている物の使い回し**：アンカーで固定した物・眠っている物は、ブロックの中心・外側の球・姿勢・当たり判定の点を作り直しません。
   プレイヤーの当たり判定・視線・ミサイルは外側の球で近い構築物だけを調べ、構築物どうしの押し出しは動いている物の近くの物だけ。
   機器の無い構築物（建物・飾り）は、機器・プログラムの処理を飛ばします。
5. **ブロックの形のつなぎ方**：階段状・L 字に置いたブロックの内側を斜面で埋めるのは、同じ種類（同じ素材・同じ機器）どうしだけです。
   違う種類どうし（建物の内装と外装など）は階段状のまま、なめらかにはつながりません。

### 完全剛体モード（ワールド設定）

新しいワールドは **完全剛体モードが ON** で作ります（新規作成の画面で切り替えられます。あとからワールド設定でも変えられます）。
ワールド設定の「完全剛体モード」を ON にすると、衝突・速度・加速度にかかわらず、構築物は丸ごと1つの剛体として動きます
（曲がらない・ちぎれない・壊れない。軽く、ぶつけても形が保たれます）。

- 地面との接触は剛体として解きます（めり込んだ分を並進＋回転でまとめて押し戻し、摩擦をかける）。跳ね返らずに着地し、
  傾いて落ちれば転がる・倒れるといった動きをします。構築物どうしもぶつかって押し合います。
- **アクチュエーターが動いている間**は、構築物をアクチュエーターの前後で「部分」に分け、部分ごとの剛体を関節でつないで動かします
  （例：人型ロボットなら胴・頭・上腕・前腕・太もも・すね（足）がそれぞれ剛体）。
  - 部分 = アクチュエーターの出力面の結合を切ったときにつながっているブロックのまとまり。出力面の先が別の道で
    土台とつながっている（輪になっている）関節は、回せないので固定のまま扱います。
  - 関節は、出力面の中心どうしを合わせ、軸の傾きをそろえ、軸まわりの角度を回転角に合わせます（反作用は土台側にもかかります）。
    押し出し・引き込みは、アクチュエーター自身の出力面をずらして先の部分を押します。
  - 電力・信号・配管は今までどおり構築物全体で共有なので、部分に分かれても通ります。
  - 止まって 1 秒たつと、今の形のまま1つの剛体に戻ります。動き出せばまた部分ごとになります。
- ブロックを足したり外したりしたあとも、そのときの形で剛体（または部分ごとの剛体）になります。
- 液体・粘土などの柔らかい素材も、構築物の一部として固まったまま動きます。
- 遠くの構築物のレール（軌道計算）はこのモードでも使います。画面左上に「完全剛体」と表示されます。

### 高速化（Rust の物理コア・numba・複数コア）

物理演算の重い部分（形合わせ・結合・当たり判定・惑星の地形・構築物どうしの押し出しの組探し）は、
Rust で書いた物理コア `alpedia_core`（`native/`）があればそれで計算します（画面左上に「物理:Rust」）。
構築物1つの1サブステップ（重力・浮力・減衰・形合わせ・結合・回転ジョイント・地面との接触・塑性変形・ちぎれの判定、
剛体・完全剛体・関節つき剛体も）と、構築物どうしの押し出しは Rust でまとめて計算し、その間は Python を止めないので、
構築物ごとの計算が複数コアで本当に同時に進みます。MOD のプログラム・ブロックプログラム・ゲームの決まりごとは Python のままです。
作り方は `native/README.md`（Windows は `native\build_windows.bat` をダブルクリック）。無いときは次の numba 版で計算します。

物理演算の重い部分（形合わせ・結合・当たり判定・表面の形の計算）は `numba`（必須）で機械語に変換して実行し、
構築物ごとの計算を複数の CPU コアで同時に進めます。大きな構築物（256 ブロック以上）は、その中のブロックごとの計算を複数コアに分けます。

- 初回起動時だけ変換に数十秒かかります（裏で行うので、その間も遊べます。2回目以降は保存済みを使うので数秒）。
- `config/settings.json` の `physics.threads` で使うスレッド数を指定できます（0 = 自動）。
- `physics.backend`：`"auto"`（Rust があれば使う。既定）／`"rust"`／`"python"`（numba だけ）。

## コード構成（コア・MOD・画面）

Rust などへの書き直しに向けて、物理とワールドの「コア」と、それ以外をはっきり分けています。

| 区分 | 場所 | 中身 |
|---|---|---|
| コア | `main/` 直下 | ワールド（`world.py`）・構築物と物理（`construct.py`, `fastphys.py`, `shape.py`, `geom.py`）・機器（`devices.py`, `actuator.py`, `airtight.py`）・惑星・プレイヤー・無線・定義の読み込み |
| コアの決まりごと | `hooks.py` / `modcode.py` / `devstate.py` / `savefmt.py` / `control.py` | MOD のプログラムの口／その読み込み／機器の状態の形／セーブの形／スクリプトから構築物を読み書きする窓口 |
| Rust の物理コア | `native/alpedia_core/`（`lib/` にビルドしたもの） | 構築物の1サブステップまるごと（`Body`）・形合わせ・結合・関節つき剛体・惑星の地形と接触・重力・近い点の組。Python 側の入り口は `native.py`・`construct.py`（`_native_begin`）・`fastphys.py`・`planet.py` |
| スクリプト | `scripting.py`, `blocks.py` | `api` は `control.Port` だけを通して構築物を読み書きする |
| マルチプレイ | `net.py` / `netsync.py` / `netserver.py` / `netclient.py` | 通信の形・LAN の中のワールド探し／状態の送り方・受け方／ホスト側／参加者側 |
| MOD | `mods/` | 定義（JSON）とプログラム（`code/`）。本体に入っている MOD：街（`mods/city`：街・暮らしと経済・政治・その画面）、シナリオモード（`mods/story`）と、その再現ブロック・登場人物・場所（`mods/scenario_blocks`・`soredemo_cast`・`lunaport`・`amatsu`）、かわいいモーション（`mods/cute_motions`） |
| 画面 | `main/client/` | ursina による描画と操作。MOD の画面は `client/addon_hooks.py` の口で足す |
| 中身 | `content.py`, `tutorial*.py`, `modmeta.py`, `extensions.py`, `scenery.py` | スクリプトの説明、新しいワールドを作る（MOD のワールドの形）、MOD の情報と依存関係、MOD の機器（custom）とブロックの口、景色の箱と地図 |

- コアは MOD のプログラムと `main.client` を読み込みません（`tests/test_core.py` が確かめます）。
- MOD のプログラムは `hooks.Addon` を継承し、当たり判定の箱（`colliders`）・物理の前後（`before_physics` / `after_physics`）・
  視線（`raycast`）・プレイヤーの押し出し（`push_sphere`）・E の操作（`interact`）・置いたとき（`on_placed`）・
  読み込み/保存（`on_load` / `on_save`）、資源のルール（`pay` / `refund` / `on_dig` / `on_water` / `interact_device` / `jetpack`）の口を
  必要なものだけ使います。書き方は `mods/README.md`。
- 機器の状態（`state`）に入れてよい項目と型は `devstate.py` の表で決まっています。読み込み時に形をそろえ、
  計算中だけの項目（推進機の噴射量など）は保存しません。セーブの各ファイルの形は `savefmt.py` で調べます（違う所はログに出ます）。
- 自動テスト: `python -m unittest discover -s tests -v`（コアだけで動く物理・スクリプト・無線・保存・MOD の口と、サバイバル・街を画面なしで読み込むテスト）。
- 古い形式のワールド（world.json に `creative` / `cities` があるもの）は、読み込むときに MOD に読み替えます
  （サバイバルだったら遊び方 survival、街ありだったら city の MOD。保存すると新しい形式になります）。

## 現時点の制限（今後の拡張ポイント）

- 惑星の地形は距離場＋掘削跡で表現しており、プレイヤーの構築物のような頂点ボクセルではありません
  （掘ることはできますが、地形が崩れたりはしません）。地球型の惑星の水は静止した水面で、流れません。
- 惑星は固定位置（公転なし）、大気抵抗なし。
- 大きな構築物ほど柔らかくなりやすい（反復計算の回数は `config/settings.json` の physics で調整可）。
- ゲーム内スクリプトのサンドボックスは簡易的なものです。他人のスクリプトは中身を確認してから使ってください。
- 日本語フォントは Windows の メイリオ／游ゴシック 等を自動で使います。見つからない場合は
  `config/settings.json` の `graphics.font` にフォントファイルのパスを書いてください。
