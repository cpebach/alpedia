## 0. 要点

- Alpedia は、物理演算つきのボクセルサンドボックス（Minecraft × KSP）。サンドボックス本体に加えて、約 100 分のシナリオ（全 15 章・ムービー 11 本）、サバイバル、街と経済、LAN マルチプレイ、MOD、ゲーム内プログラミング（ブロック／Python）まで一通り動く。
- 2026-11-13 の1日で、**本体のほぼ全部を Python から Rust に書き直した**（物理・ワールド・機器・画面・UI・音・通信）。Python に残るのは入口の薄いファイル（約 2,400 行）と MOD、Rust は約 5 万行。Panda3D・ursina・numba・scipy・scikit-image は使わなくなった。
- いちばん大きい問題は、**この書き直しに周辺が追いついていない**こと：
  1. パッケージ版（配る物）が書き直し前の中身のまま
  2. 書き直しを含む 69 コミットが GitHub に上がっていない（＋ビルドに要る修正が未コミット）
  3. ムービーを作る道具（`movies/`）が、消した古い画面に頼ったまま
  4. 文書（README など）に古い説明が残っている
  5. Rust 側の単体テストが無く、確かめは Python のテストだけ
- 自動テスト（110 件）は、今の開発版ですべて通る（「3. 確かめた結果」）。

## 2. できること

### 2.1 遊び方

| 遊び方 | 内容 |
|---|---|
| シナリオ | ストーリー vol.1「それでも」。序章〜エピローグの 15 章、約 100 分。章の区切りにムービー 11 本、BGM、エンドロール。章ごとに操作とプログラミングを1つずつ学ぶ作り（歩く → 掘る → バルブと推進機 → オープンループ → フィードバック制御 → 無線とドローン → 採掘と工場 → 乗り物 → 修理 → 自動航行 → 迎撃プログラム → 変形ロボット → 総復習）。章の自動保存・やり直し、ムービーの見直し、セリフの記録、1 分たつと出るヒントつき |
| サバイバル | 置くのに資源が要る。掘る → 精錬 → 加工 → 燃料 → 飛ぶ → 軌道 → 月、の7つの目標 |

### 2.2 世界と物理

- **ボクセルの構築物**：丸いブロック（かたい素材は多面体）。結合・ちぎれ・塑性変形・再結合で、固体・液体・靭性・硬度のちがいを表す。ちぎれると別の構築物に分かれる。
- **完全剛体モード**（既定 ON）：構築物を丸ごと1つの剛体で計算（軽い）。アクチュエーターが動く間は関節つきの剛体になる。OFF でやわらかいブロック。
- **惑星**：球体（テラ）と地球型（ガイア：山・海・池・洞窟）。月と小惑星3つ。掘れる。水には浮力と抵抗、プレイヤーは泳げる。
- **世界の広さ**：制限なし（浮動原点）。遠くの構築物は軌道だけ計算（レール）、さらに遠くは停止、条件つきの自動削除。
- **気密**：ブロックで囲んだ空洞を見つけて、通気口で与圧・減圧。

### 2.3 機器

推進機（発電も兼ねる）・タンク・配管・バルブ・バッテリー・太陽光パネル・手回し発電機・精錬機・加工機・通気口・アクチュエーター3種（ローター・ピストン・ヒンジ）・アンカー・ライト・アンテナ（無線）・コンピューター・操縦席。

- 電力と信号は同じ構築物の中で共有（配線なし）。配管だけは連続したブロックでつなぐ。
- 機器に名前を付けて、まとめて／個別に制御できる。

### 2.4 ゲーム内プログラミング

- **ブロック（ノード）プログラミング**：スクラッチ風。イベント・制御・演算・センサー・変数・通信・矢印（ベクトル）・機器の操作。保存すると Python に変換して実行。
- **Python**：`tick(api)` を周期的に呼ぶ。外部エディタで編集して保存すると自動で読み直す。軌道情報・無線・表示・機器の操作の API。
- 見本：ルミナス号の月への自動航行、迎撃艦の砲塔制御、変形ロボット「ツバメ」（ロケット ⇔ 人型）。

### 2.5 作った物の出し入れ

- **OBJ 出力（F9）／読み込み（F8）**：ゲーム内の構築物はブロック・機器・結合・プログラムごと再現。外部の OBJ（Blender など）は大きさ・細かさ・素材を決めてボクセル化。
- **設計図**：シナリオの船・ロボット・艦と、はじめのロケット／工場／気密室が F8 に最初から並ぶ。

### 2.6 MOD

- 定義だけの MOD（素材・機器・惑星・プレイヤー・資源を JSON で。`extends` で派生）と、プログラムを持つ MOD（Python。ワールド側 `Addon`・画面側 `ClientAddon`）。
- 独自の機器（`custom`）、ブロックプログラムのブロック、スクリプトの API、モーション、VRM の見た目を足せる。依存（`requires`）は自動で入る。
- 本体に入っている MOD：

| MOD | 中身 |
|---|---|
| `city` | サイバーパンクの街（地表・軌道・小惑星に自動でできる）。通貨・NPC・取引・部屋・地域ごとの値段、マップ、都市の思惑（征服・攻撃と助言）。軌道都市は押して動かせ、落とせる |
| `story` | シナリオモード（ストーリー vol.1） |
| `scenario_blocks` | 迎撃砲塔・レーダー・ミサイル発射機・推進モジュール・燃料ポンプ |
| `soredemo_cast` | 登場人物 |
| `lunaport` / `amatsu` | 月の街ルナ・ポート／軌道都市アマツ |
| `skinmodel(dummy)` | VRM の見た目（骨・揺れもの・まばたき） |
| `cute_motions` | カメラモードで選ぶモーション |
| `bgm` | BGM の曲の一覧（曲のファイルは git 管理外） |
| `example_mod` | 定義だけの MOD の例 |

### 2.7 画面・操作・音

- Rust（wgpu）の画面。メニュー、ゲーム設定、キーの変更、一時停止メニュー、インベントリ、機器の設定、三人称、F3 の重さ表示、フルスクリーン。
- **カメラモード**：自撮り・撮影用。モーション・視野角・傾き、写真の保存。
- **タッチ操作**：仮想ジョイスティックと画面のボタン（複数の指に対応）。
- **音**：BGM（章・ムービーに合わせて）と効果音（数式で作った wav）。音量は別々。
- ムービーの再生（PyAV で読み解く）。日本語の入力（変換も）。

### 2.8 開発・配布の道具

- **ビルド**：`dev/native/build_windows.bat` で Rust の2つのモジュールを、開発版用（Python 3.10 以上）とパッケージ版用（3.12）に作る。
- **テスト**：`python -m unittest discover -s tests`（画面なしで、コア・Rust・MOD・街・マルチプレイ・シナリオの通し）。
- **描画なしの実行**：`python run.py --headless --steps 600`
- **パッケージ**：`packages/windows/パッケージを作る.bat`（同梱 Python つき、`Alpedia.exe` で起動）、`配布用zipを作る.bat`。
- **素材づくり**：設計図（`make_blueprints.py`・`make_starter_blueprints.py`）、効果音（`make_sounds.py`）、台本の文書（`make_story_doc.py`）。

### 4.3 コードの質

- **C-01（中）Rust にしたが、中身は Python の値を Rust から触る形。** `src/game/` に Python の属性の読み書き・メソッド呼び出しが約 5,600 か所ある（値を Python の dict・numpy のまま持つ）。Rust の型の検査がきかず、速さの得も限られ、Python のインタープリタのロックに頼る。読み込みは速くなった（約 10 秒 → 約 2 秒）が、ここから先は値を Rust の型で持つ形に進める必要がある。
- **C-02（中）ファイルが大きい。** `construct.rs` 3,531 行、`ursina.rs` 2,665 行、`world.rs` 2,499 行、`render.rs` 2,443 行、`block_editor.rs` 2,190 行、`viewer.rs` 2,068 行。
- **T-01（中）Rust の単体テストが 0 件。** 確かめは Python の unittest だけ。前は「Rust 版と Python 版の本体を比べる」テストが正しさの基準だったが、Python 版の本体を消したので、比べる相手はテストの中に numpy で書いた式だけになった。
- **C-03（低）MOD の画面が ursina・panda3d の「まね」に頼っている。** `ursina.rs`・`panda.rs` が古いライブラリの書き方をまねていて、MOD（`story`・`city`）は今も `from ursina import …` と書く。使っていないライブラリの名前と作法が、MOD の決まりごとになっている。
- **C-04（低）`unwrap()`・`expect()` が 124 か所。** 想定外の値で Rust が止まると、エラーの出どころが分かりにくい。
- **C-05（低）保存形式の表にない項目。** `buildkit` が `world.json` に書く `blocks` が保存形式の表（`savefmt`）に無く、読み込むたびに警告が出る。
- **C-06（低）エンドロールの「お世話になったもの」に Panda3D・Ursina が残る。** ゲームではもう使っていない（ムービーを描いたのは Panda3D なので、残すかどうかは判断しだい）。

### 4.4 速さ

- **P-01（中）シナリオで 60 fps に届かない。** 最新のログ（構築物 133、この PC）で 20〜52 fps。重いのは描画（13〜27 ms／フレーム）で、物理（4〜7 ms／回）ではない。
- **P-02（低）ワールドに入った直後の1フレームが約 1.8 秒。** 形・テクスチャ・VRM 13 体の読み込みが最初の描画に集まっている。
- **P-03（低）VRM の骨の変形を CPU でしている。** 人物が多い場面で描画の重さになりうる（1 体 2〜4 万頂点）。

### 4.5 安全

- **S-01（中）ゲーム内スクリプトのサンドボックスが簡易。** 他人の構築物（`.alp.json` にプログラムが入る）を読み込むと、そのプログラムが動く。
- **S-02（中）マルチプレイは LAN の知り合い前提。** 認証・暗号なし。参加者の操作をそのまま受け付け、参加者はホストから届いた MOD のプログラムをそのまま動かす。インターネット越しには使えない。

### 4.6 ゲームの中身の制限（前からあるもの）

- **L-01** 地形は掘れるが崩れない。水は流れない。
- **L-02** 惑星は公転しない。大気の抵抗が無い。
- **L-03** やわらかいブロックのモードでは、大きな構築物ほどやわらかくなる。
- **L-04** MOD はプレイ中に読み直せない。使っている MOD を外すと、そのワールドは始められない。
- **L-05** Python → ブロックへの変換が無い。Python の編集はゲームの外のエディタ。
- **L-06** HP・敵とのやりとりが無い（シナリオのミサイルは当たらない）。サバイバルの目標は月に降りる所まで。
- **L-07** シナリオは vol.1 の1本だけ。
